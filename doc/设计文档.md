# XWork for dsh — 设计文档

版本：0.1（草稿）
日期：2026-08-21

---

## 1. 概述

XWork for dsh 是一个基于 DeepSeek Harness（DSH）生态构建的**新桌面客户端**。它复用 DSH 的插件化运行时（Cordis + `@deepseek-ai/dsh-*` 服务插件 + Web bundle），提供一套属于自己的桌面外壳、品牌与交互，同时保留完整的 Harness 能力（agent、会话、工具、技能、工作流）。

> 一句话：**把 DSH 的"发动机"装进我们自己的"车壳"。**

## 2. 背景：DSH 生态与 DSH Desktop 架构

### 2.1 DSH 是什么

DSH（DeepSeek Harness）是一个基于 **Cordis** 的插件化 AI 工作台运行时：

- 内核：`@deepseek-ai/cordis`（Cordis 4 分支）
- 服务集：约 200 个 `@deepseek-ai/dsh-*` 插件（agent、会话、工具、技能、LLM、终端、沙箱、存储、设置……）
- 应用形态：由一个 **profile**（插件清单目录）决定，通过 patch 层组合出完整的应用

### 2.2 官方桌面（DSH Desktop）的组成

官方 `dsh-plugin-desktop` 实际是**三重身份的叠加**：

| 身份 | 文件 | 说明 |
|---|---|---|
| 宿主壳 | `lib/main.js` | Electron 主进程：`boot()` 加载插件树、创建窗口。**不是插件** |
| bundle 插件 | `package.json` | 声明 `dsh.bundle.patch`，可被 `dsh plugin add` 装进任意 profile |
| 桌面子插件 | `cordis.patch.yml` | `insert` 出 `desktop-shell`、`desktop-terminal`、`desktop-diagnostics`、`desktop-profiles`、`desktop-updates` 等 |

### 2.3 profile 机制（重要概念）

`%USERPROFILE%\.dsh\profiles\<name>\` 是一个 profile：

- `package.json`：`dsh.profile.bundles`（有序插件层）+ `dependencies`
- `cordis.yml`：空 include 根（`[]`）
- `cordis.patch.yml`：用户 patch 层
- 依赖经 pnpm workspace 装到 `profiles/node_modules`（与打包运行时共享）

启动组合顺序：**各 bundle 的 patch → profile 的 cordis.patch.yml → 机器级 patch**。

## 3. 定位与目标

### 3.1 XWork for dsh 做什么

- 独立的 Electron 桌面应用（有自己的 exe、图标、品牌名 XWork）
- 启动即用：开箱提供 DSH 的 Web 界面与 agent 能力
- 自持桌面能力：托盘、菜单、窗口管理、终端、诊断、设置面板（按需）
- 可扩展：支持通过 `dsh plugin` 安装第三方插件

### 3.2 与官方 DSH Desktop 的区别

| 维度 | DSH Desktop | XWork for dsh |
|---|---|---|
| 品牌 | DeepSeek | XWork |
| 宿主实现 | 全量（install-recovery、profile-manager、自动更新等） | 精简起步，按里程碑补齐 |
| 桌面能力 | desktop-shell 兼容模式 | 自定义 shell 与交互 |
| profile 名 | 固定 `desktop` | 独立名字（如 `xwork`） |
| 分发 | electron-builder NSIS | electron-builder（或 Tauri 备选） |

### 3.3 非目标（本期）

- 不重写 Harness 运行时（agent/会话/工具）
- 不做官方那样的自动更新与安装恢复体系（后续迭代）
- 不承诺与 DSH Desktop 二进制级兼容

## 4. 总体架构

采用**宿主 + 插件树**模式（对齐官方做法 B 起步，向 A 演进）：

```
┌─────────────────────────────────────────────────────┐
│  XWork 宿主（Electron 主进程，非插件）                 │
│  main.ts                                             │
│   ├─ 环境与运行时准备（pnpm/dsh runtime）              │
│   ├─ profile 准备（xwork profile）                    │
│   ├─ 模块解析钩子（打包运行时 <-> profile 依赖）        │
│   ├─ boot() 加载 Harness 插件树                       │
│   └─ 窗口 / 托盘 / 菜单 / 终端 等原生桌面能力            │
├─────────────────────────────────────────────────────┤
│  Harness 插件树（由 boot() 组装）                     │
│   ├─ @deepseek-ai/dsh-base            （核心服务）     │
│   ├─ @deepseek-ai/dsh-web-app         （Web UI）      │
│   └─ xwork-* 桌面子插件（通过 cordis.patch.yml insert）│
│        ├─ xwork-shell   窗口/渲染器接入                │
│        ├─ xwork-terminal 终端                         │
│        └─ xwork-diagnostics 诊断/日志                  │
├─────────────────────────────────────────────────────┤
│  数据层（%USERPROFILE%\.dsh\，与 DSH 共享）            │
│  sessions / storages / settings.yaml / credentials    │
└─────────────────────────────────────────────────────┘
```

关键决策：

1. **宿主与插件分离**：应用外壳（Electron 壳 + 原生能力）不作为 bundle 插件，直接写在主进程；只有需要进入 Harness 生命周期（事件、服务、设置面板、工具、会话）的能力才写成插件。
2. **复用 `@deepseek-ai/dsh-app-boot` 的 `boot()` / profile 机制**，不重写。
3. **profile 独立命名**（如 `xwork`），避免与官方 `desktop` profile 冲突；底层仍由 `@deepseek-ai/dsh-web-app` 提供 UI。
4. **模块解析两锚点**：`dsh-plugin-desktop` 式钩子——`xwork` 自身解析到打包运行时，`@deepseek-ai/*` 从 profile 依赖解析（参考 `module-resolution.js`）。

## 5. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 运行时 | Node.js ≥ 24（或 22.19+） | DSH 引擎要求（`^22.19 || >=24`） |
| 包管理 | pnpm 11.x（Corepack 固定） | 官方一致，workspace 友好 |
| 桌面框架 | Electron 43.x | 与 DSH 一致，生态成熟 |
| 语言 | TypeScript（host 与 client 分离的构建） | 与官方仓库一致 |
| 宿主/内核复用 | `@deepseek-ai/dsh-app-boot`、`@deepseek-ai/cordis` | 不重写运行时 |
| UI | 复用 `dsh-web-app` Web bundle（默认）；后续可注入自定义 client | 第一版快速可用 |
| 打包 | electron-builder（asar + asarUnpack，NSIS） | 官方同款配置 |
| 日志 | 自有 file log（JSONL + 兜底导出） | 便于诊断 |

## 7. 核心模块设计

### 7.1 主进程启动流程（对齐官方 `main.js` 精简版）

```
app.whenReady()
  → loadLayeredEnv()
  → 准备 pnpm runtime（打包的 pnpm，用于 profile 依赖）
  → prepareXworkProfile("xwork")      // 确保 profile 存在、组装 bundles/patch
  → installProfilePackageResolver()   // ESM resolve 钩子
  → boot("xwork-for-dsh", rootConfig, patches, prepare, bareModuleBaseUrl)
        // 插件树并发启动
  → ctx.provide(desktopRuntime / desktopPnpmBootstrap 等)
  → 挂载自定义桌面服务（shell、terminal、diagnostics）
  → runtime.mount() → BrowserWindow → rendererBoot 健康检查
```

失败路径：捕获 boot/渲染器失败 → 日志 + 兜底错误窗口 → 按状态退出。

### 7.2 profile 准备（`prepareXworkProfile`）

- profile 名固定 `xwork`（或配置文件可选）
- bundles：`@deepseek-ai/dsh-base` + `@deepseek-ai/dsh-web-app`（必须，否则抛错）
- 在该 bundle 层后追加 XWork 自己的 `cordis.patch.yml`（insert xwork 桌面子插件）
- 追加 profile 用户层 patch、机器级 patch
- 校验必需行（webserver、settings、shell 行）后返回 patches

### 7.3 桌面子插件（v1）

| 插件 | 职责 | 接入方式 |
|---|---|---|
| xwork-shell | BrowserWindow 渲染 Web UI、窗口管理、退出/重启 | patch insert + 主进程原生协作 |
| xwork-terminal | 内置终端（复用以 `@deepseek-ai/dsh-terminal` 能力或自研） | 可选 |
| xwork-diagnostics | 收集日志/系统信息，导出 zip | 可选（对标官方 diagnostics） |

### 7.4 数据与配置

- 沿用 DSH 的数据目录 `%USERPROFILE%\.dsh\`（sessions/storages/settings/credentials），与 Web 版互通
- XWork 自身设置放独立 namespace（如 `xwork`），存于 `settings.yaml`
- 用户态 profile 名与数据目录名需在文档与常量中固定，避免与官方冲突

## 9. 开发里程碑

| 里程碑 | 目标 | 验收标准 |
|---|---|---|
| **M0 环境就绪** | Node 24 + Corepack pnpm + 本项目骨架 | `pnpm install`、`pnpm run typecheck` 通过 |
| **M1 最小可运行** | 宿主 + 空 profile 弹出窗口，加载 `dsh-web-app` UI | 双击启动 → 看到 DSH Web 界面 → 能发起会话 |
| **M2 桌面子插件** | 托盘、窗口管理、日志/诊断导出 | 系统托盘可用、诊断 zip 可导出 |

建议顺序：**M1 先行**，其余按需裁剪。

## 10. 风险与注意事项

1. **版本耦合**：宿主与 `@deepseek-ai/dsh-*` 包版本必须匹配（此前 2.0.0/2.0.1 不匹配直接导致官方桌面无法启动）；锁定版本并在 CI 校验。
2. **profile 名冲突**：不要用 `desktop`；使用独立名 `xwork`。
3. **打包运行时 vs profile 依赖**：模块解析钩子是正确加载的关键，必须做对（参考 `module-resolution.js`）。
4. **Electron 版本**：`dsh-plugin-desktop` 的 `peerDependencies` 固定 `electron@43.4.0`，宿主应锁同一版本，避免原生模块（koffi 等）ABI 不兼容。
5. **Windows 特定**：终端/沙箱依赖 PowerShell；ACL 沙箱需注意。
6. **不承诺兼容**：本期不实现官方 install-recovery / 自动更新，升级路径需另行设计。
